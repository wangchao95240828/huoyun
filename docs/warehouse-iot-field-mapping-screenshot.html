仓库 IoT 接口字段与现有数据库对应关系

第一阶段可不新增表：用 shipments + cartons + scan_events 支撑 check / pickup / update 联调

shipments 运单表

字段用途
id运单主键
tenant_id租户隔离
customer_id客户
shipment_no对应 shipment_number
status运单状态
destination_country目的国家
destination_postal_code目的邮编
warehouse_in_at入仓时间
measured_at量方/称重时间

cartons 箱子表

字段用途
id箱子主键
tenant_id租户隔离
shipment_id关联 shipments.id
carton_no对应 item_number
tracking_no面单号兜底匹配
actual_weight_kg对应 weight
length_cm对应 length
width_cm对应 width
height_cm对应 height
cbm体积，用于后续智能排柜

scan_events 扫描事件表

字段用途
id事件主键
tenant_id租户隔离
warehouse_id仓库
shipment_id关联 shipments.id
carton_id关联 cartons.id
tracking_no面单号
scan_type对应 action
scanned_at对应 time
device_code设备号，可从 ext 取
raw_payload保存 ext / 原始请求

仓库请求字段映射

仓库字段数据库字段说明
actionscan_events.scan_typecheck / pickup / update
item_numbercartons.carton_no箱号主匹配字段；如果扫面单号则兜底匹配 tracking_no
shipment_numbershipments.shipment_no运单号，用于校验箱子归属
timescan_events.scanned_at也参与 token 验签
token不入业务表只用于验签
extscan_events.raw_payload保存原始请求，方便排查
weight / length / width / heightcartons 实测重量尺寸字段后续智能排柜直接使用这些数据
select s.id as shipment_id, c.id as carton_id from shipments s join cartons c on c.shipment_id = s.id where s.shipment_no = :shipment_number and (c.carton_no = :item_number or c.tracking_no = :item_number);
结论：第一阶段可以不新增 IoT 表，直接用 shipments 查运单、cartons 查箱子并回写重量尺寸、scan_events 记录扫描事件。
