# 登录与权限基础模块需求

版本：2026-05-06

## 背景

主系统要复刻并优化 ACC 和新智慧，不应继续使用旧系统账号体系作为核心身份来源。登录、权限、审计、客户账号和 API 凭证必须落在主系统自己的数据库中。

## 本阶段目标

1. 内部员工可以登录主系统。
2. 登录后前端保存短期访问 token，后续系统管理接口带 token 请求。
3. 后端能识别当前用户、租户、角色和权限。
4. 权限设计支持菜单、API、审批、分公司范围后续扩展。
5. 登录成功、失败、锁定、退出都能留下审计基础。
6. 默认管理员可以用于本地初始化和演示。

## 用户类型

| 类型 | 说明 | 表 |
| --- | --- | --- |
| 内部员工 | 运营、财务、客服、管理员 | `users` |
| 客户门户用户 | 客户自助下单、查账、查轨迹 | `customer_accounts` |
| API 调用方 | 客户 API、系统集成、后续承运商回调 | `api_credentials` |

本阶段优先完成内部员工登录；客户门户和 API 凭证先完成表结构。

## 登录需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| AUTH-001 | 用户使用租户、用户名、密码登录 | `POST /api/auth/login` 返回 token 和用户信息 |
| AUTH-002 | 密码不能明文保存 | `users.password_hash` 使用 PBKDF2 哈希 |
| AUTH-003 | 登录失败要记录 | `auth_login_events` 有失败记录和原因 |
| AUTH-004 | 连续失败要临时锁定 | 5 次失败后锁定 15 分钟 |
| AUTH-005 | 登录成功更新最后登录时间 | `users.last_login_at` 被更新 |
| AUTH-006 | 登录会话可撤销 | `POST /api/auth/logout` 更新 `user_sessions.revoked_at` |
| AUTH-007 | 前端未登录只能看到登录页 | Web 首屏显示登录表单 |
| AUTH-008 | 系统管理接口要求登录 | `/api/sys/*` 非登录接口无 token 返回 401 |

## 权限需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| PERM-001 | 用户可以有多个角色 | `user_roles` 支持多角色 |
| PERM-002 | 角色可以绑定多个权限 | `role_permissions` 支持多权限 |
| PERM-003 | 权限采用资源 + 动作 | `permissions.resource/action/code` 明确 |
| PERM-004 | 管理员拥有全部权限 | `ADMIN` 角色绑定全部权限 |
| PERM-005 | 财务主管拥有财务读写和审批权限 | `FINANCE_MANAGER` 有应收、应付、账本、资金、审批权限 |
| PERM-006 | 操作员拥有订单和仓库操作权限 | `OPERATOR` 有订单维护和仓库扫描权限 |
| PERM-007 | 后续支持分公司范围 | `user_roles.scope_type/scope_id` 已预留 |

## 默认角色

| 角色 | 说明 | 关键权限 |
| --- | --- | --- |
| `ADMIN` | 系统管理员 | 全部权限 |
| `FINANCE_MANAGER` | 财务主管 | 应收、应付、账本、资金账户、审批 |
| `FINANCE_CLERK` | 财务专员 | 账单、导入、对账 |
| `OPERATOR` | 操作员 | 订单、仓库、派送比价 |

| 租户 | 用户名 | 密码 | 说明 |

## 非本阶段范围

| 功能 | 原因 |
| --- | --- |
| 双因素认证 | 先完成主流程 |
| SSO/企业微信登录 | 后续按客户环境接入 |
| 客户门户完整权限 | 本阶段只建表，不做完整门户 |
| API 签名校验 | `api_credentials` 已建表，签名流程后续实现 |
| 字段级权限 | 先做资源级和动作级权限 |

## 完成定义

登录页可用，默认管理员可登录，`/api/auth/me` 能返回用户、角色、权限；系统管理接口要求 token；数据库有正式的用户、角色、权限、会话和登录审计表。
