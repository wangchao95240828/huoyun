## 一、系统总览

xqt-saas 完整替代 ACC PHP 系统，业务流程：

```
新建客户 → 客户授信 → 制单 → 提交 → 配载/出货 → 收货签收 → 出账单 → 客户付款 → 月结 → GL报表
```

主菜单 8 大组：

| 菜单组 | 对应 ACC | 关键 tab |
|---|---|---|
| 制单中心 | 制单/订单中心 | 快件订单、新建订单、状态分类 |
| 配载中心 | 配载中心 | 快件查询、今日快件、配载、转运 |
| 客服中心 | 收货+问题件 | 收货、问题件、签收、赔偿 |
| 销售中心 | 销售/客户管理 | 客户、报价、潜客、提成 |
| 核算中心 | 核算中心 | 运费/成本/月结/GL 三表 |
| 财务中心 | 财务中心 | 账单、收款、付款、罚款 |
| 数据管理 | 系统设置 | 国家、邮编、HS、银行、税号 |
| 人事组织 | 人事 | 员工、工资、考勤、社保 |
| API 对接 | API 接入 | 客户凭证、调用日志、Webhook |

## 二、每日例行操作

### 1. 上午开工：检查队列与告警

1. 登录 → 仪表盘看「待办」
2. 浏览：
   - 制单中心 → 快件订单 → 状态=DRAFT（待客户/客服补充）
   - 制单中心 → 状态=SUBMITTED（待审核）
   - 配载中心 → 今日快件
   - 客服中心 → 问题件（PENDING 状态）
3. 看监控告警：http://8.148.227.76:9090/alerts （应该全部 inactive）

### 2. 新建订单（替代 ACC 制单）

操作步骤：
1. 制单中心 → 快件订单 → 「新建订单」
2. 7 个分区按序填：
   - **基本信息**: 客户单号、日期、客户（下拉）
   - **发货渠道**: 产品、制单账号、包裹类型、电池、特殊货物、标签类型
   - **货物信息**: 英文/中文品名、件数、重量、体积、电池代码
   - **发票信息**: 货币、申报价值、运费、保险、附加服务、备注
   - **收件人**: 仓库地址（下拉）、目的地、公司、姓名、电话、地址等
   - **发件人**: 留空走默认
   - **进口商 (IOR)**: 选预设模板自动填，或手填
   - **申报明细**: 多行品名+单价+HS码
   - **装箱单**: 箱号+重量+尺寸
3. 保存 → 状态 = DRAFT
4. 点订单行「详情」可看 9 个分区完整数据

### 3. 提交订单 → 自动取号

1. DRAFT 订单 → 点「提交」
2. 后端自动：
   - 报价（RateEngine 跑费率）→ 拆 AR/AP 多费用行
   - 取号（UPS/FedEx 真实接口）→ 落 carton.tracking_no
   - 扣余额（balance_ledger 写 PREPAY 行）
   - 状态切到 SUBMITTED
3. 失败原因看「订单详情 → 操作历史」

### 4. 出账 → 收款

1. 财务中心 → 客户账单 → 「批量出账」
2. 选订单/费用 → 生成 invoice
3. 客户付款后：财务中心 → 客户收款 → 「录入收款」
4. 后端自动写 balance_ledger PAYMENT 行 + 生成 GL 凭证

### 5. 月底关账

1. 核算中心 → 月结
2. 选 period=YYYY-MM → 「预览」→ 看本月总收入/总支出/净利润
3. 确认无误 → 「关账」
4. 后端自动：
   - 生成结转凭证 V-CLOSE-YYYY-MM
   - 收入/费用全部结转到 3103 本年利润
   - acc_period_locks 写锁定记录（之后所有 < 该 period 的会计动作都会被阻断）

## 四、客户 API 对接

### 给客户创建 API 凭证

1. API 对接中心 → 客户凭证 → 「新建凭证」
2. 选客户 + 勾权限 scope
3. **保存时一次性显示 secret 明文** ← 必须立即发给客户，关掉就拿不到
4. 客户保留 access_key + secret，签名时用：
   ```
   sign = md5(join(',', sorted_values) + secret)
   headers: X-API-User / X-API-Time / X-API-Version / X-API-Sign
   ```

### 客户 API 端点

| 操作 | 路径 | 方法 |
|---|---|---|
| 建订单 | /api/customer-api/orders | POST |
| 提交订单 | /api/customer-api/orders/{no}/submit | POST |
| 取消订单 | /api/customer-api/orders/{no}/cancel | POST |
| 查状态 | /api/customer-api/orders/status | POST |
| 同步轨迹 | /api/customer-api/orders/sync | POST |

签名失败查 API 调用日志 → 看 error_code（SIGN_MISMATCH / UNKNOWN_USER / TIME_DRIFT）

### 客户凭证维护

- **轮换 secret**: API 凭证页 → 行内「轮换」按钮 → 新 secret 显示一次
- **吊销**: 行内「吊销」→ 状态变 REVOKED → 该客户立刻无法对接
- **看调用流水**: API 对接中心 → 调用日志 tab → 按 customer 筛选

## 五、多级审批

阈值（可在策略页改）：
- 单笔 < 50,000 → 1 级
- 50,000 ≤ < 500,000 → 2 级
- ≥ 500,000 → 3 级

工作流：
1. 发起人提单（如：大额退款）→ 自动落 approval_requests PENDING
2. 审批人在「核算中心 → 待审批」看到
3. APPROVE / REJECT 各级 → 收齐人数自动 APPROVED
4. 任一级 REJECT 整请求 REJECTED
5. 自己提的不能自己批

### 监控告警

- Prometheus UI: http://8.148.227.76:9090
- 告警状态: http://8.148.227.76:9090/alerts
- 抓取目标: http://8.148.227.76:9090/targets

7 条告警规则:

| 告警 | 触发 | 处理 |
|---|---|---|
| BackendDown | 进程不可达 1min | `systemctl restart xqt-backend` + 看 journalctl |
| HighErrorRate | 5xx > 5% 持续 5min | 看 journalctl 排查 |
| SlowResponse | P95 > 2s 持续 10min | 看慢查询 / Hikari 连接 |
| HighHeapUsage | 堆 > 85% 持续 10min | jmap -histo:live <pid> 找泄漏 |
| FullGcFrequent | FullGC > 0.5/s | 加堆 / 调优 |
| NoOrderCreatedFor1Hour | 业务时段 1h 无新单 | 检查前端 / 客户 API |
| HighRateLimitRejects | > 20/min | 看是否爬虫 / 攻击 |

## 七、常见问题排错

### 「订单提交失败：报价失败」

- 看 charges 表 evidence 字段
- 多半是渠道账号没配 (acc_channel_accounts) 或费率表缺
- 数据管理 → 销售价格 → 补价表

### 「订单提交失败：余额不足」

- 客户预付余额账户 (financial_accounts owner=CUSTOMER) 不够
- 财务中心 → 客户余额 → 充值

### 「客户 API 一直 401 SIGN_MISMATCH」

- 在 api_credentials 重置 secret（reset-secret 按钮）
- 把新明文 secret 重发给客户
- ⚠️ 历史已修复 sha256 存储 bug，现在创建的所有 credential 都 OK

### 「期间被锁定」

- 月结后回不到上月改账，必须先解锁：
- 核算中心 → 月结状态 → 「解除锁定」（需 ADMIN）
- 改完再「重新关账」

### 「前端看不到订单」

- 看登录账号的 user_grade 和 bound_customer_id
- bound_customer_id 不空 → 只能看自己客户的订单（Range filter）
- ADMIN (user_grade=9, bound=null) 看全部

## 十、紧急联系

- 后端服务挂：先 `systemctl restart xqt-backend`，5 秒内不起 → 看 `journalctl -u xqt-backend --since '5 min ago'`
- DB 连不上：看 systemd postgresql / docker 状态
- 客户对接故障：查 api_call_logs 表里最近 100 条 error_code
- 前端白屏：F12 → Network 看是不是 4xx/5xx
- 监控异常：http://8.148.227.76:9090/targets 看哪个 target down
