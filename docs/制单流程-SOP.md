# 跨境货代 制单全流程 SOP (Standard Operating Procedure)

**系统**: XQT-SaaS 多租户跨境包裹货代平台  
**入口**: http://8.148.227.76/  (admin / admin123)  
**版本**: feat/acc-full-migration-2026-05-26  

> SOP 目标: 让一个新员工照着做 10 分钟内能下完第一个单。每一步都标了**入口**+**预期**+**异常处理**。

# 📋 完整业务流 (8 步, 平均 7 分钟/单)

```
┌──────────────────────────────────────────────────────────────────┐
│ Step 1: 客户准备 (新客户/老客户)                                       │
│ Step 2: 实物入仓 (DWS 称重) — 可选                                    │
│ Step 3: 下单 (单笔 / 批量 xlsx) ⭐                                    │
│ Step 4: 报价确认 (RateEngine 自动) + 临时额度检查                       │
│ Step 5: 提交承运商 (Submit → 拿 tracking)                            │
│ Step 6: 配载 (3D Bin Packing) — 仅海运/卡运                           │
│ Step 7: 跟踪 + 异常处理 (退件/问题件)                                  │
│ Step 8: 账单结算 (生成账单 → 收款核销 → 利润)                          │
└──────────────────────────────────────────────────────────────────┘
```

# Step 1: 客户准备 (单次 5 分钟)

## 1.1 新客户建档

**入口**: 左菜单 → 销售中心 → 客户管理 → `+ 新增`

**必填**:
- 客户编码 (例: `SELLER-DEMO`, 全英文大写)
- 客户名称 (中文)
- 联系人 / 电话
- 默认结算币种 (USD / CNY)
- 信用额度 (USD/CNY 的赊账上限, 例 10000)
- 结算方式 (MONTHLY / QUARTERLY)

**预期**:
- 客户主档列表立刻新增 1 行
- 系统自动建 1 个 financial_accounts.balance 行 (USD 起始余额 0)

## 1.2 (可选) 客户价格策略 R-12

**场景**: 我们对这客户加价 / 给折扣

**入口**: 销售中心 → 客户价格策略 → `+ 新增`

**字段**:
- customerId: 选目标客户
- channelId: 选目标渠道 (例 UPS-GROUND-US)
- commission_rate: `1.20` = 加价 20% / `0.90` = 9 折
- floor_amount: 最低运费保护 (避免低于成本)
- effective_from: 生效日期

**预期**: 该客户下单时, AR = 渠道商价 × commission_rate, 不影响其他客户

## 1.3 (可选) 临时额度 ⭐

**场景**: 客户欠款没付, 但要继续下单 — 我们给个临时垫资

**公式**: `余额 = 总付款额 + 临时额度 - 使用金额`

**入口**: 财务中心 → 应收 → 客户账户 (临时额度) → 该客户行点 💳 紫色按钮

**字段**:
- 币种: USD / CNY
- 新临时额度: 例 500 (USD)
- 备注: "客户预付到账前临时垫资"

**预期**:
- balance_ledger 立刻写 1 行 TEMP_CREDIT
- 客户可用余额 = 之前 + 500
- 应收款项目 / 应收实收对比 立刻反映

# Step 3: 下单 ⭐ (核心环节)

## 3.1 单笔下单 (最常见)

**入口**: 委托运输 → 制单中心 → 快件订单 → `+ 新增`

**必填字段** (按弹窗顺序):

| 字段 | 示例 | 说明 |
|---|---|---|
| 客户单号 | `SO-20260629-001` | 客户的内部单号 (R-1 同单不能重复) |
| 客户 | SELLER-DEMO | 下拉选已建好的客户 |
| 销售产品 | UPS-GROUND-US | 渠道, 决定算价规则 |
| 收件人 | John Doe | 收件人名 |
| 国家 / 邮编 | US / 90210 | 决定 zone 计算 |
| 收货地址 | 123 Test Ave | |
| 城市 / 州 | LA / CA | |
| 重量 (kg) | 1.5 | 实重 |
| 体积 (CBM) | 0.05 (可选) | 系统自动算体积重 |
| 件数 | 1 | |
| 申报品名 / 数量 / 价格 / HS 编码 | (海关申报必填) | |

**点 提交 后预期**:
- 列表新增 1 行 status='DRAFT' (草稿)
- 运费列自动算出 (例 12.47 USD, 含 R-12 9 折)
- 成本列自动算出 (例 13.85 USD, 渠道商真价)
- 计费重列 = max(实重, 体积重)

## 3.2 ⭐ 批量下单 (R-2 xlsx 导入)

**场景**: 客户一次给 100 单, 单笔录入太慢

**入口**: 委托运输 → 快件订单 → 右上角 `📥 xlsx 批量导单` (蓝色按钮)

**5 步**:
1. **选客户** (必选, 整批挂同一客户)
2. **下载模板** (24 列中文表头 xlsx)
3. 自己填好数据保存
4. **拖拽 xlsx 到弹窗** → 点「预览」
5. 看红色错误行 → 改 xlsx 或修复 → 点「提交导入」

**预期**:
- Toast: `导入完成: 成功 N / 失败 M`
- 列表立刻新增 N 行
- 失败行返错误说明 (例: "客户编码不存在" / "邮编格式错")

## 3.3 R-1 同单去重保护

**场景**: 不小心同客户 + 同单号录 2 次

**自动行为**:
- 第二次提交弹窗: "客户 + 单号已存在, 是否合并 / 覆盖 / 取消"
- **合并**: 把新数据 patch 进旧单 (重量/收件人覆盖)
- **覆盖**: 旧单标 VOID, 新单建
- **取消**: 不动

# Step 4: 报价 + 临时额度检查

## 4.1 自动算价 (RateEngine)

**触发时机**: 提交订单后自动跑

**算法**:
```
chargeable_weight = max(实重, 体积重 = volumeCbm × 1_000_000 / dimFactor)
zone = 按 lane 分支:
  · US-LAST-MILE: 邮编前 3 位查 ups_zone_mappings
  · US-OCEAN-EXPRESS: 邮编首位 → USE/USM/USW (海派)
  · US-OCEAN-TRUCK: 仓库代码 → 一区/二区/... (卡派)
freight = 阶梯价 (zone × chargeable_weight)
fuel = freight × fuel_rate (该周燃油率)
AR = (freight + fuel) × commission_rate (R-12)
AP = freight + fuel (我们成本)
```

**真值示例 (UPS-GROUND-US, 1.5 kg → 33101)**:
- AR (客户付): 12.47 USD (= 13.85 × 0.9)
- AP (我们成本): 13.85 USD
- 利润: -1.38 USD (负 = R-12 commission_rate=0.9 是亏损模型)

## 4.2 临时额度自动校验

**场景**: 客户欠款 > 信用额度, 又没临时额度

**自动行为**:
- 提交订单时检查: 客户当前余额 + 信用额度 + 临时额度 >= 本单 AR?
- 否 → 弹窗拦截 "客户信用不足, 是否设置临时额度?"
- 是 → 直接放行

# Step 5: 提交承运商 (Submit)

## 5.1 单笔提交

**入口**: 制单中心 → 快件订单 → 选行 → 行操作 ✅ 提交

**自动行为**:
1. 调用 CarrierGateway (按 channel_account.provider_code 路由)
   - UPS / FEDEX / KARRIO / NOOP (占位)
2. 拿到 tracking_no (服务商单号)
3. 生成 shipment + cartons
4. 写 AR + AP charges
5. status 从 'DRAFT' → 'SUBMITTED'

## 5.2 批量提交

**入口**: 制单中心 → 未提交 → 全选 → 顶部 `批量提交`

**预期**: 一次推 N 单给承运商, 失败的弹错误清单

# Step 6: 配载 (仅海运/卡运)

## 6.1 3D Bin Packing 求解

**入口**: 配载中心 → 配载管理 → `+ 新增方案`

**字段**:
- 柜规格: 20GP / 40GP / 40HQ
- 货物清单: 选当前待装 carton (自动从未发运 shipment 拉)
- LIFO 启用 (后入先出, 卸货顺序优化)

**点 求解 后**:
- 系统跑 3D Bin Packing 算法
- 输出方案号 + 体积利用率 + 4 象限重量分布
- 重心偏移 > 10% 自动加 ⚠ 警告

## 6.2 3D 立体视图

**入口**: 配载中心 → 3D 配载方案 → 点方案号

**预期**: 弹大 modal (1400px), 显示集装箱内 carton 真实摆放 (不同客户不同颜色块, 拖拽旋转, 滚轮缩放)

# Step 7: 跟踪 + 异常

## 7.1 轮询 tracking

**入口**: 制单中心 → 追踪快递 → 选订单 → 批量追踪

**自动行为**: 调承运商 API 拉最新 tracking event, 写 tracks 表

## 7.2 异常订单

**入口**: 配载中心 → 异常订单 (status=EXCEPTION)

**典型异常**:
- 地址错误 / 收件人拒收 → 客服中心 → 问题件总览 立案
- 海关查验 / 滞留 → 自动写 tracking event, 客服跟进
- 退回 → 客服中心 → 退件管理

## 7.3 退件流程

**入口**: 客服中心 → 退件管理 → `+ 新增退件`

**字段**: 单号 / 退件原因 / 应退金额 / 备注

**自动行为**:
- 审核后写 R-9 RESTATE charge (退还应收)
- 同步 supplier_fine (向承运商索赔)
- balance_ledger 写 REFUND 流水

# Step 8: 账单结算 ⭐

## 8.1 生成客户账单

**入口**: 财务中心 → 客户账单 → 顶部 `生成账单`

**5 步**:
1. **选客户** (例 SELLER-DEMO)
2. ⚠ 系统自动提示**该客户历史出账状态** (黄框):
   ```
   USD: 共 3 张账单, 累计 56.31 USD, 最近 2026-06-24
   CNY: 共 1 张账单, 累计 943.50 CNY, 最近 2026-05-08
   ```
3. **选币种 / 起始日期 / 截止日期** (默认最近 30 天)
4. 点 `🔍 预览可开账明细` 看 charges 拆分:
   - 🟢 BILLABLE 可开 (8 笔)
   - 🟣 BILLED 已开 (4 笔 灰显)
   - 🔴 VOIDED 作废 (2 笔 红显)
   - 🟡 UNAUDITED 未审 (6 笔 黄显)
5. 默认全选 BILLABLE → 点 `生成`

**预期**:
- Toast: `账单生成成功: INV20260629... 共 7 笔, 总额 52.84 USD`
- 财务中心 → 已出账 tab 立刻看到新账单行

## 8.2 ⭐ 导出账单 xlsx (奥沃星样式)

**入口**: 财务中心 → 已出账 (或客户账单) → 行操作 `📥 导出`

**预期**:
- 浏览器自动下载 `账单_INV*.xlsx`
- 2 个 sheet:
  - Sheet 1 「订单列表」 27 列 (含差异列)
  - Sheet 2 「货件明细」 23 列 (carton 装箱+申报)
- 跟你给的 `奥沃星6.24.xlsx` 1:1 对齐

## 8.3 打印对账单

**入口**: 财务中心 → 已出账 → 行操作 `📄 打印对账单`

**预期**:
- 弹新窗口 HTML 对账单 (公司抬头 + 明细表 + 合计)
- Ctrl+P 另存 PDF 发给客户

## 8.4 客户收款

**入口**: 财务中心 → 客户账单 → 行操作 `快速收款`

**字段**:
- 金额 (= 账单未付额, 或部分付款)
- 收款方式 (银行转账 / 现金 / 支票)
- 收款日期
- 银行账号

**预期**:
- payments 表新增 1 行 audit_status='PENDING'
- 审核后 → AUDITED → 触发 BalanceLedgerSideEffect:
  - balance_ledger 写 3 条 (CUSTOMER RECEIPT / COMPANY PAYMENT / INVOICE CREDIT)
  - charges.paid_amount += 收款额
  - customer_invoices.paid_amount += 收款额
  - 应收实收对比立刻平账

## 8.5 R-8 单笔补收 (实际跟报价差)

**场景**: 承运商真账单回来发现少收了 1.50 USD

**入口**: 核算中心 → 应收运费 → 选 charge 行 → 点 ✏️ 补收按钮

**字段**:
- 模式: **DELTA** (差值, 推荐) / OVERWRITE (覆盖, 仅未审用)
- 新金额: 比原值大 1.50
- 备注: "DWS 复称 / 承运商重核"

**预期**:
- 生成 ADJUST charge (source_type='RESTATE', source_charge_id=原 charge)
- **自动审核** (R-8 修复后, status='AUDITED')
- **自动触发 balance_ledger** 扣客户欠款账户 +1.50
- R-9 聚合列: 原 charge「补收 +」立刻 +1.50

## 8.6 R-7 批量补收 (xlsx)

**入口**: 核算中心 → 应收运费 → 顶部 `📤 xlsx 批量补收`

**字段**: 4 列模板 (运单号 / 新金额 / 新重量 / 备注)

**用途**: 承运商月底发 xlsx 含 N 单的真实重量, 一次性补收差额

# 🚨 高频异常处理

## E1. 客户欠款超额度, 拒下单

**触发**: Step 4 自动校验失败

**处理**:
1. 财务中心 → 应收实收对比 看具体欠多少
2. 财务中心 → 应收 → 客户账户 (临时额度) → 设临时额度
3. 客户付清 → 销售收款 → 余额恢复

## E2. 承运商真账单 vs 我们成本不符 (R-4)

**入口**: 财务中心 → 渠道账单对比

**流程**:
1. 收到承运商 xlsx 月度账单
2. 点 `📥 上传渠道账单 xlsx` 输入 partnerCode + currency
3. 系统自动对比内部 cost charge vs 承运商账单
4. 差异行列在表里 (差 > 5% 红色标识)
5. 点 ✅ 确认核销 or ❌ 申诉

## E3. 客户拒付 / 退件

**入口**: 客服中心 → 退件管理 → `+ 新增`

**流程**:
1. 客户报退件
2. 在退件管理立案 (上传图片 + 单据)
3. 财务审核退件金额
4. 同意 → 写 RESTATE charge (减应收) + supplier_fine (向承运商索赔)
5. balance_ledger 写 REFUND
6. 客户余额回退

## E4. 已开账单要作废 / 改

**入口**: 财务中心 → 已出账 → 选行 → `❌ 作废`

**前提**: invoice_status != 'PAID' (已付不能直接作废, 先退款再作废)

**自动行为**:
- invoice.status = 'VOID'
- 关联 charges.settlement_status 回 'UNSETTLED'
- 这些 charge 可重新开账单
